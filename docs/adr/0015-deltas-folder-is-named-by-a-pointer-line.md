# The Deltas folder is named by a pointer line, and an ignored one is asked about once

ADR 0004 put the Delta in git because a future agent only sees what is in the codebase, and wrote it to `docs/deltas/`. Shared repos often ignore `docs/` (generated API docs, personal notes), and then that promise breaks silently: the Delta is written, the skill never commits, nobody is told, and teammates' agents and their `/design-lessons` never see it. Fixing it by hand has a trap too: under a `docs/` rule, `!docs/deltas/` re-includes nothing, because git does not look inside an ignored folder.

So the folder is no longer a constant. A `Design deltas:` line in `AGENTS.md`, `CLAUDE.md` or `CLAUDE.local.md` names it, the same way `Design rules:` names the rules file (ADR 0009); without the line it stays `docs/deltas/`, so existing projects keep working. Before writing a Delta, `/design-delta` asks git whether the Delta would be ignored. If so, it asks once: move the folder somewhere tracked (`design/deltas/` recommended), un-ignore it (rewriting `docs/` to `docs/*` when needed, and only in a `.gitignore` the repo owns), or keep it on this machine. The last is a fair choice for a team that wants only the distilled design rules shared and not the raw Deltas; the line then says `(local)` and lives in `CLAUDE.local.md`, kept out of git, because it is one person's choice and another person on the same repo may choose differently. The answer lives in the line or `.gitignore`, so it is asked once per clone. A background run cannot ask; it writes where it would anyway and says so in its note. The Nudge reads the same line, and its offer says when git ignores the folder.

Not chosen: moving the default to a dot folder such as `.kddesign/`, which is as likely to be ignored, hidden in editors, and breaks every existing project; and keeping Deltas outside the repo (Notion, the Artifact), which loses ADR 0004's reason for having them at all.
