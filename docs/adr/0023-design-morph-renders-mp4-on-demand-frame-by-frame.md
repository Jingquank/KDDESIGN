# The MP4 is made on demand, frame by frame

Most films are watched on their page; a video is for posting elsewhere. Rendering one costs minutes of browser time per act and an ffmpeg install, so it happens only with `--mp4` or when asked afterwards, and the hand-over says how to ask. It is rendered frame by frame, never screen-recorded: seek the film, wait two animation frames, take a CDP screenshot of the stage alone with guides on, then encode at 60 fps (H.264, CRF 16, yuv420p, faststart). A recording drops frames whenever the machine is busy and captures the player around the stage; a seek-and-shoot render is exact at any speed and shows only the film. The frame tools take whatever page object the user's chosen browser gives (anything with `evaluate` and `cdp`), so no browser is written into the skill.
