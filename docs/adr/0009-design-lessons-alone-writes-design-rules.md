# design-lessons is its own skill and the only writer of design rules

Turning Deltas into permanent rules could have been a mode of `/design-delta`. It is a separate skill instead, because the two run at different paces (every branch versus every few weeks), because a skill loads its whole instructions on every run, and above all so that one skill holds the right to change a project's rules: `/design-delta` only reads them, to note a `Breaks:` line when a Change goes against one, and `crazy-prototype` does not read them at all, so prototypes stay free. Following Vercel's evidence intake, a candidate needs two independent sources, counted as events (a commit, a conversation, a Note), or one Note from the user, before it reaches the Design Lessons Review. Pick sheets are not evidence at all: a Pick or a ✗ is a quick call among rough Ideas, too random to teach a rule, so the Deltas are the only input, and a prototype round reaches a rule only through what shipped. Nothing changes without the user's pasted Verdicts. Because its only input is the Deltas, it no longer has to be remembered: `/design-delta` runs it at its own hand-over once 5 Deltas have piled up since the last review, and the review's date is recorded when it is offered, so an unanswered review is not offered again until 5 more arrive. Rules go into the project's existing design guidance when it has one, else `DESIGN.md`, with one pointer line in `AGENTS.md` or `CLAUDE.md`, so a project never ends up with two rule files.
