# design-delta records pushed work by itself, as text, and the Nudge commits it

ADR 0008 let Round 1 stand without an answer because the user mostly looked and moved on. In practice KD stopped looking at all: the Kinds the agent sets are right, the Changelog is not read, and Approve on the Nudge is a key pressed for nothing. Meanwhile a background run took 26 minutes (ADR 0031), two thirds of it capturing stills for a page nobody opens, and the Nudge guessed when work had Settled by asking a small model to read ten messages.

So a project can ask to be recorded passively. Its `Design deltas:` line says `(auto)`, written by `/design-delta` after one question in a hand run, and from then on:

- **A push is the trigger.** Pushing UI work is the user approving it, a fact where Settled was a guess. The Nudge looks at session start, after a turn, and after every `git push` Claude runs, and compares the newest Delta's After with the branch's upstream; a push from another terminal is found at the next look. The small model still reads the diff, but only to say whether a user could see it.
- **Nobody is asked.** The mod starts the background agent itself with `$.agent.spawn`. It does not put a request into the conversation in the user's name, as ADR 0014's **1** does: with no key pressed, that line would tell auto mode's review something that did not happen. When the engine refuses the spawn, the Nudge falls back to the one-key offer for the same pushed range, and that press is real.
- **The run writes text only** (`--passive`): the diff and the transcripts become a Delta, with no browser, no stills, no page and no Final. Visibility is judged from the code, and a hunk that cannot be judged is a Change marked "(not seen)", which gives up ADR 0030's fresh eye for these runs. A line sourced to a conversation quotes the user's words.
- **The Nudge commits the Delta**: one commit holding that file alone, whatever else is staged, `[skip ci]`, and pushed on any branch but the default one, where it stays local for the next push. Written after the push, an uncommitted Delta would miss the branch's last push, the one before a merge. It commits nothing when the user has moved to another branch or git ignores the folder. This is the one place KDDESIGN commits; the skills still never do.
- **A passive run never takes the band.** It is one line in the status line while it runs and one toast when the Delta is kept. Only a Design Lessons Review it chained brings the band up, because that is a question for the user.

Push approves what changed, not why. A Delta's reasons and its rule candidates are the agent's reading, and with the Changelog's Notes gone the Verdicts of a Design Lessons Review are the only place a person checks them. Two things follow. The review shows each source in the user's own words, not a paraphrase. And since no Note can lift a candidate over the bar any more, a conversation source in which the user states a general preference is marked `stated` and clears it alone, as a Note did; a remark about one place stays one source of two.

The opt-in is per project and per person: the `(auto)` line and a hand run of `/design-delta` on this machine (ADR 0012), so a teammate's line never starts runs on someone else's account. `/design-delta` by hand is unchanged and now means "make the page": the way to show a set of Changes to someone.

Not chosen: starting the run by a line in the conversation with no key pressed (above); a headless `claude -p` started by the mod, which nothing in the session could follow or stop; letting the background agent commit, since a commit limited to one path is safer as a fixed command than as an instruction; pushing on the default branch, where a push may deploy or be refused; capturing stills lazily when a candidate reaches a review, because old commits are hard to run and transcripts do not last.

Since then: ADR 0042 gives a passive Delta its Before and After from page snapshots, and with them a page. ADR 0043 removes Notes, Final and Approve from the hand-run page as well.
