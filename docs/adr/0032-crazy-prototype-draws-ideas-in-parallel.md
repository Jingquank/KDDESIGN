# crazy-prototype thinks alone and draws in parallel

crazy-prototype is worth what it delivers fast, many and varied. One agent drew every Idea one after another, and a full interface mock runs to hundreds of lines, so the drawing was most of a Round and the page grew slower with every Idea added.

So with 6 or more Ideas the run splits the work. The main agent alone writes the Idea list (each Idea's answer to what the Brief is for, and how it works) and the page shell with its ticks and copy button. Subagents then draw 2 to 4 Ideas each, at once, as fragments scoped to their own `#idea-N`, and the main agent drops them into the shell and publishes. Fresh contexts also keep one Idea's look from leaking into the next, which the skill already asks for.

Not chosen: letting each subagent think up its own Ideas, since agents that cannot see each other's lists converge on the same few answers; a review pass over the fragments, since the user's Picks are the review and checks cost the speed the skill exists for; splitting small Rounds, where reading the Brief and the design system again costs more than the drawing saves.
