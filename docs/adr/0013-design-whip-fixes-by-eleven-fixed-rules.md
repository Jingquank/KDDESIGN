# design-whip fixes by eleven fixed rules, not by the project's design rules

`/design-whip` is a whip, not a guide: it runs only by hand, checks the UI changes of this conversation (else of this branch) against eleven rules KD wrote, and fixes every violation on the spot instead of reporting first, since the fixes are in git. It could have read the project's design rules too, and let an accepted Rule win when the two disagree (an accepted `rule/icon-buttons-have-labels` against "never add labels"). It does not: the eleven rules are the whole check, so a run means the same thing in every project and never has to judge between two rule sets. The design rules stay outside the whip: written by `/design-lessons` from Verdicts or edited directly (ADR 0025), and read by `/design-delta`. Unlike the design rules, the whip also reaches `/crazy-prototype` pages: a prototype stays free in what it explores, so the whip never removes an Idea, but the mock inside each Idea is held to the same rules as shipped code. It reads code only and opens no browser, so it stays quick; seeing the result Before and After is `/design-delta`'s job, where the whip's fixes arrive as Changes like any other.
