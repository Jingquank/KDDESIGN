# break-it keeps its crazy data in the browser

`/break-it` does what the craziest real person of a product would do: upload 100 photos, press Delete five times, submit twice, invite people. It runs in KD's own browsers, where KD is logged in, so doing those things for real would leave real records, and on production real harm. It could have refused anything but local environments, or asked before every dangerous action. It does neither: since it tests only what the UI shows and how it behaves, never the backend, it holds every write in the page behind a layer over `fetch` and `XMLHttpRequest` and answers with a fake response (success, or a failure, timeout or slow reply when the Stunt calls for one), and shapes what a surface shows by faking reads or editing the page instead of creating records. Only what the layer cannot hold (a WebSocket, a native form post, a payment iframe, an OAuth redirect) is asked about first. That is why a production URL may be tested, and why each run first proves the layer by sending one write and checking it never left the browser. Everything it makes lives in the tab or the scratchpad and is thrown away: `/break-it` never writes into the project, and its fixes go through `/crazy-prototype`.
